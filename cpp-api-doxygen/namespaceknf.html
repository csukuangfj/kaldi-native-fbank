void knf::ApplyCmvn ( const MatrixD & stats,
const CmvnOptions & opts,
MatrixF * feats )

Apply cmvn to feats in place (kaldi ApplyCmvn / ApplyCmvnReverse).

Let \( c = \mathrm{stats}(0, \mathrm{dim}) \) be the frame count, \( \mu_d = \mathrm{stats}(0, d) / c \) the mean and, when norm_vars is true, \( \sigma_d^2 = \mathrm{stats}(1, d) / c - \mu_d^2 \) the variance of dimension \( d \).

Forward (opts.reverse == false), applied to every frame \( x \):

\[ x_d \leftarrow x_d - \mu_d \]

and, if opts.norm_vars:

\[ x_d \leftarrow (x_d - \mu_d) / \sigma_d \]

Reverse (opts.reverse == true) undoes the normalization:

\[ x_d \leftarrow x_d + \mu_d \]

and, if opts.norm_vars:

\[ x_d \leftarrow x_d \cdot \sigma_d + \mu_d \]

Accepts 1-row (mean-only) or 2-row stats; requesting norm_vars with 1-row stats is an error (same as kaldi).

Parameters
[in]stats1-row or 2-row cmvn stats; see InitCmvnStats().
[in]optsOptions: norm_vars (normalize variances), reverse (undo cmvn).
[in,out]featsFeature matrix of size num_frames x dim; each row is normalized in place.

◆ ComputeDeltas()

MatrixF knf::ComputeDeltas ( const DeltaOptions & opts,
const MatrixF & feats )

Compute delta (dynamic) features.

This is kaldi's add-deltas (kaldi DeltaFeatures / ComputeDeltas in src/feat/feature-functions.cc), same arithmetic. The \( i \)-th block of the output is the \( i \)-th order regression delta; with \( N = \) opts.window, the first-order delta of frame \( t \) is

\[ \Delta_t = \frac{\sum_{j=-N}^{N} j\, x_{\mathrm{clamp}(t+j)}} {2 \sum_{j=1}^{N} j^2} \]

where out-of-range frames clamp to the first/last frame (edge frames are replicated). Higher orders apply the same operator recursively to the previous order's window (kaldi's scales_ recursion). The output rows are [x_t, \Delta_t, \Delta^2_t, \ldots], i.e. the block order is baseline first, then increasing delta order.

Parameters
[in]optsOrder/window; see DeltaOptions.
[in]featsFeature matrix of size T x D (T > 0, D > 0).
Returns
The matrix of size T x (D * (order + 1)).

The regression windows themselves are computed as follows. With \( N \) = opts.window, the first-order window is

\[ w^{(1)}_j = \frac{j}{\sum_{k=-N}^{N} k^2} = \frac{j}{2 \sum_{k=1}^{N} k^2}, \qquad j = -N, \ldots, N \]

and each higher-order window is the discrete convolution of the previous window with \( w^{(1)} \) (kaldi's scales_ recursion):

\[ w^{(i)} = w^{(i-1)} * w^{(1)}, \qquad w^{(0)} = [1] \]

so \( w^{(i)} \) is the \( i \)-fold convolution of \( w^{(1)} \) (its length is 1 + 2 * i * window).

Motivation.** The spectrum of speech is strongly non-stationary: the trajectory* of the spectrum over time carries information that the static spectrum does not. Furui (1986) showed that appending the time derivative of the spectrum (the "delta") significantly improves recognition. HTK refined this into the regression-based formulation used here: instead of a raw difference such as \( x_{t+1} - x_{t-1} \), the local slope of a least-squares line is estimated over a window of \( 2N+1 \) frames, which is less sensitive to noise and to isolated outliers. kaldi's DeltaFeatures implements the same HTK formulation.

Why this definition.** The first-order window is the slope of the least-squares straight line fitted to the frames around \( t \) — the classic HTK regression delta that kaldi's DeltaFeatures implements. Fitting \( y(j) = a + b\, j \) to \( x_{t+j} \), \( j = -N, \ldots, N \), by minimizing \( \sum_j (x_{t+j} - a - b\, j)^2 \), and using \( \sum_j j = 0 \) (which decouples the intercept from the slope), the slope estimate is

\[ b = \frac{\sum_j j\, x_{t+j}}{\sum_j j^2} = \sum_j w^{(1)}_j\, x_{t+j} \]

so \( w^{(1)}_j = j / \sum_k k^2 \) is exactly the least-squares slope estimator: \( \Delta_t = b \) is the local slope of the fitted line, i.e. a least-squares estimate of the first derivative (the \( \sum_j j^2 \) normalizer is the OLS denominator).

Higher orders apply the same slope estimator to the previous order's output ( \( \Delta^2 \) is "the slope of the slope"). Since the slope estimator is a linear filter with kernel \( w^{(1)} \), filtering an already-filtered sequence convolves the kernels, hence \( w^{(i)} = w^{(i-1)} * w^{(1)} \) with support growing to \( \pm i N \). Note this is recursive slope-of-slope — it is not identical to the \( i \)-th derivative of a degree- \( i \) least-squares polynomial fitted over the wider \( \pm iN \) window.

Normalizing by \( \sum_j j^2 \) at every order keeps each block on the scale of a true \( i \)-th derivative, and edge frames replicate the first/last frame so the frame count is preserved and the regression "sees" a locally constant signal at the borders. This is the standard HTK/kaldi dynamic-feature formulation.

Furui, "Speaker-independent isolated word recognition using dynamic features of speech spectrum", IEEE Trans. Acoustics, Speech, and Signal Processing, 1986, https://doi.org/10.1109/TASSP.1986.1164788

How the convolution is computed.** The discrete convolution of two windows \( a \) (indices \( -A..A \)) and \( b \) (indices \( -B..B \)) is the window \( c = a * b \) (indices \( -(A+B)..A+B \)) defined by

\[ c_m = \sum_{k} a_k \, b_{m-k} \]

where \( a_k \) and \( b_k \) are zero outside their index ranges. For the second-order window this is

\[ w^{(2)}_m = \sum_{k=-N}^{N} w^{(1)}_k \, w^{(1)}_{m-k} \]

Window example 1 - N = 1, orders 1 to 3.** \( \sum_{k=-1}^{1} k^2 = 2 \), so the first-order window is \( w^{(1)}_j = j/2 = [-0.5, 0, 0.5] \). The convolution \( w^{(2)}_m = \sum_k w^{(1)}_k w^{(1)}_{m-k} \) term by term:

\( m = -2 \): \( w^{(1)}_{-1} w^{(1)}_{-1} = (-0.5)(-0.5) = 0.25 \) \( m = -1 \): \( w^{(1)}_{-1} w^{(1)}_{0} + w^{(1)}_{0} w^{(1)}_{-1} = (-0.5)(0) + (0)(-0.5) = 0 \) \( m = 0 \): \( w^{(1)}_{-1} w^{(1)}_{1} + w^{(1)}_{0} w^{(1)}_{0} + w^{(1)}_{1} w^{(1)}_{-1} = (-0.5)(0.5) + 0 + (0.5)(-0.5) = -0.5 \) \( m = 1 \): \( w^{(1)}_{0} w^{(1)}_{1} + w^{(1)}_{1} w^{(1)}_{0} = 0 \) \( m = 2 \): \( w^{(1)}_{1} w^{(1)}_{1} = (0.5)(0.5) = 0.25 \)

which gives \( w^{(2)} = [0.25, 0, -0.5, 0, 0.25] \). Convolving once more, \( w^{(3)} = w^{(2)} * w^{(1)} \); e.g. \( w^{(3)}_{-3} = w^{(1)}_{-1} w^{(2)}_{-2} = (-0.5)(0.25) = -0.125 \) and \( w^{(3)}_{-1} = w^{(1)}_{-1} w^{(2)}_{0} + w^{(1)}_{1} w^{(2)}_{-2} = (-0.5)(-0.5) + (0.5)(0.25) = 0.375 \). The full chain for N = 1:

\( w^{(0)} = [1] \) \( w^{(1)} = [-0.5, 0, 0.5] \) \( w^{(2)} = [0.25, 0, -0.5, 0, 0.25] \) \( w^{(3)} = [-0.125, 0, 0.375, 0, -0.375, 0, 0.125] \)

Window example 2 - N = 2.** \( \sum_{k=-2}^{2} k^2 = 10 \), so \( w^{(1)}_j = j/10 = [-0.2, -0.1, 0, 0.1, 0.2] \). Two sample convolution sums for \( w^{(2)} = w^{(1)} * w^{(1)} \):

\( w^{(2)}_{0} = \sum_k w^{(1)}_k w^{(1)}_{-k} = 2(-0.2)(0.2) + 2(-0.1)(0.1) + (0)(0) = -0.1 \) \( w^{(2)}_{4} = w^{(1)}_{2} w^{(1)}_{2} = (0.2)(0.2) = 0.04 \)

The full 9-tap window is \( w^{(2)} = [0.04, 0.04, 0.01, -0.04, -0.1, -0.04, 0.01, 0.04, 0.04] \).

Example 1 - full derivation** (x = [1, 2, 4], order=2, window=1). With the windows derived above, \( w^{(1)} = [-0.5, 0, 0.5] \) and \( w^{(2)} = [0.25, 0, -0.5, 0, 0.25] \), i.e.

\[ \Delta_t = -0.5\, x_{t-1} + 0.5\, x_{t+1} \]

\[ \Delta^2_t = 0.25\, x_{t-2} - 0.5\, x_t + 0.25\, x_{t+2} \]

For the 1-D input x = [1, 2, 4] (out-of-range frames clamp to the first/last frame) the output rows [x_t, \Delta_t, \Delta^2_t] are:

[1, 0.5, 0.75] // t=0: D = -0.5*1 + 0.5*2; D2 = 0.25*1 - 0.5*1 + 0.25*4

◆ GetWindow()

std::vector< float > knf::GetWindow ( const std::string & window_type,
int32_t window_size,
float blackman_coeff = 0.42 )

Return the window coefficients of the given window type.

Let \( N \) be window_size, \( n = 0, \ldots, N-1 \) the sample index, and \( a = 2\pi/(N-1) \). The supported window types and their formulas are:

  • "hanning": \( w[n] = 0.5 - 0.5 \cos(a n) \)
  • "hann": \( w[n] = 0.5 - 0.5 \cos(a n) \) with \( a = 2\pi/N \) (periodic variant; see https://pytorch.org/docs/stable/generated/torch.hann_window.html)
  • "sine": \( w[n] = \sin(0.5\,a\,n) = \sin(\pi n/(N-1)) \)
  • "hamming": \( w[n] = 0.54 - 0.46 \cos(a n) \)
  • "povey": \( w[n] = (0.5 - 0.5 \cos(a n))^{0.85} \) (like hamming but goes to zero at the edges)
  • "rectangular": \( w[n] = 1 \)
  • "blackman": \( w[n] = c - 0.5 \cos(a n) + (0.5 - c) \cos(2 a n) \) where \( c = \) blackman_coeff.

If window_type is not one of the above, an error is logged with KNF_LOGE() and std::invalid_argument is thrown.

window_sizeNumber of samples in the window.
blackman_coeffConstant coefficient for generalized Blackman window; only used if window_type is "blackman".
Returns

◆ InitCmvnStats()

void knf::InitCmvnStats ( int32_t dim,
MatrixD * stats )

Initialize cmvn stats to zeros in the FULL 2-row layout.

The output matrix stats is resized to 2 x (dim+1) and set to zero. Its layout matches kaldi's cmvn.ark format exactly:

\[ \mathrm{stats} = \left( \begin{array}{cccc|c} S_1 & S_2 & \cdots & S_D & c \\ Q_1 & Q_2 & \cdots & Q_D & - \end{array} \right) \]

Row 0 (above): columns 0 .. dim-1 hold the sums \( S_d = \sum_t x_t(d) \) of each feature dimension; the last column \( c \) holds the frame count (sum of weights).

Row 1 (below): columns 0 .. dim-1 hold the sums of squares \( Q_d = \sum_t x_t(d)^2 \); the last column is unused.

This is the form produced/consumed by AccCmvnStats(), ComputeCmvnStats() and ApplyCmvn() with norm_vars=true.

Note: ApplyCmvn() also accepts 1-row (mean-only) stats, where only row 0 above is present; this function, however, only produces the 2-row form used for accumulating both mean and variance.

Parameters
[in]dimFeature dimension of the frames that will be accumulated, e.g. 39 for 39-dim MFCC.
[out]statsThe output stats matrix, resized to 2 x (dim+1).

◆ ResampleWaveform()

void knf::ResampleWaveform ( float orig_freq,
const VectorF & wave,
float new_freq,
VectorF * new_wave )

Downsample or upsample a waveform (convenience wrapper).

This is a convenience wrapper for the class 'LinearResample'. The low-pass filter cutoff used in 'LinearResample' is 0.99 of the Nyquist, where the Nyquist is half of the minimum of (orig_freq, new_freq). The resampling is done with a symmetric FIR filter with N_z (number of zeros) as 6.

We compared the downsampling results with those from the sox resampling toolkit. Sox's design is inspired by Laurent De Soras' paper, https://ccrma.stanford.edu/~jos/resample/Implementation.html

Note: we expect that while orig_freq and new_freq are floats, they are actually required to have exact integer values (like 16000 or 8000) with a ratio between them that can be expressed as a rational number with reasonably small integer factors.

Parameters
[in]orig_freqOriginal sample rate in Hz.
[in]waveThe input waveform.
[in]new_freqDesired sample rate in Hz.
[out]new_waveThe resampled waveform (resized internally).

◆ kGoldenDotProductTol

double knf::kGoldenDotProductTol = 1e-4
constexpr

Comparison tolerance for golden matrices whose kaldi reference was produced by matrix multiplications or long dot products (the LDA transform-feats outputs and the pitch NCCF): kaldi's BLAS and Eigen accumulate the sums in different orders, which gives per-platform float noise of up to a few 1e-5.

Observed maxima for the LDA goldens: 1.5e-5 (linux-arm32), 1.1e-5 (windows-x64), 2.7e-5 (windows-arm64); the golden-generating platform agrees at <= 1e-5. 1e-4 leaves headroom while still catching real implementation differences (>= 1e-3). Pipelines of sequential reductions (cmvn/delta/splice) compare at the tighter 1e-5 instead.

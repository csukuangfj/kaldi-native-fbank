Pitch

Full doxygen reference (auto-generated from the headers): C++ API doxygen

Header: kaldi-native-fbank/csrc/feature-pitch.h — the equivalent of kaldi's compute-and-process-kaldi-pitch-feats (pitch-functions, the ICASSP 2014 pitch algorithm of Ghahremani et al.).

Streaming:

knf::PitchExtractionOptions pitch_opts;
pitch_opts.min_f0 = 50;
pitch_opts.max_f0 = 500;
knf::ProcessPitchOptions process_opts;   // 3-dim output by default

knf::OnlinePitch pitch(pitch_opts, process_opts);
pitch.AcceptWaveform(pitch_opts.samp_freq, samples, n);
pitch.InputFinished();
for (int32_t t = 0; t != pitch.NumFramesReady(); ++t) {
  std::vector<float> feat = pitch.GetFrame(t);  // size == pitch.Dim()
}

Batch (kaldi's compute-and-process-kaldi-pitch-feats):

knf::MatrixF feats = knf::ComputeAndProcessKaldiPitch(
    pitch_opts, process_opts, samples, n);  // (num_frames, Dim())

int32_t max_frames_latency = 0

The maximum number of frames of latency that we allow the pitch processing to introduce, for online operation.

If you set this to a large value, there would be no inaccuracy from the Viterbi traceback (but it might make you wait to see the pitch). Normalization right context is more relevant for online latency; you can leave this at zero. Kaldi --max-frames-latency.

int32_t frames_per_chunk = 0

Only relevant for ComputeAndProcessKaldiPitch.

If nonzero, we provide the input as chunks of this size. This affects the energy normalization which has a small effect on the resulting features, especially at the beginning of a file. For best compatibility with online operation, you might want to set this to a small value, like one frame. Kaldi --frames-per-chunk.

bool simulate_first_pass_online = false

Only relevant for ComputeAndProcessKaldiPitch, and only if frames_per_chunk is nonzero.

If true, we output the features as soon as they are available, which simulates the first-pass features you would get in online decoding. If false, the features you get will be the same as those available at the end of the utterance, after InputFinished() has been called (e.g. during lattice rescoring). Kaldi --simulate-first-pass-online.

int32_t recompute_frame = 500

Only relevant for online operation or when emulating online operation (e.g.

when setting frames_per_chunk). This is the frame-index on which we recompute the NCCF (e.g. frame-index 500 = after 5 seconds); if the segment ends before this we do it when the segment ends. We do this by re-computing the signal average energy, which affects the NCCF via the "ballast term", scaling the resampled NCCF by a factor derived from the average change in the "ballast term", and re-doing the backtrace computation. Making this infinity would be the most exact, but would introduce unwanted latency at the end of long utterances, for little benefit. Kaldi --recompute-frame.

bool nccf_ballast_online = false

This is a "hidden config" used only for testing the online pitch extraction.

If true, we compute the signal root-mean-squared for the ballast term only up to the current frame, rather than the end of the current chunk of signal. This makes the output insensitive to the chunking, which is useful for testing purposes. Kaldi --nccf-ballast-online.

bool snip_edges = true

If false, the incomplete frames near the ending edge won't be snipped, so that the number of frames is the file size divided by the frame-shift.

This makes different types of features give the same number of frames. Kaldi --snip-edges. (Note: unlike the other feature types, kaldi's pitch extractor defaults this to true.)

struct ProcessPitchOptions

Options for the pitch post-processing stage (kaldi's ProcessPitchOptions).

Determines which features are produced from the raw (NCCF, pitch) pair. With the defaults, each frame is the 3-dimensional (POV-feature, normalized-log-pitch, delta-log-pitch) used by kaldi's compute-and-process-kaldi-pitch-feats; see src/feat/pitch-functions.h.

class OnlinePitch

Streaming pitch extraction with post-processing (kaldi's OnlinePitchFeature + OnlineProcessPitch).

This is the streaming interface of kaldi's compute-and-process-kaldi-pitch-feats: it consumes waveform chunks and produces the processed pitch features (by default 3-dimensional: POV, normalized-log-pitch, delta-pitch).

Usage mirrors OnlineMfcc: feed the waveform with AcceptWaveform(), call InputFinished() when no more data is coming, then read frames with GetFrame(). Frames may become available before InputFinished() (with latency: see normalization_right_context and max_frames_latency), and InputFinished() flushes the remainder.

Features for a given frame may be revised as more data arrives (the Viterbi traceback and the normalization window settle over time), except for the delta-pitch noise which is drawn once per frame. After InputFinished(), the features are final and stable.

See also

PitchExtractionOptions, ProcessPitchOptions, ComputeAndProcessKaldiPitch, OnlineMfcc

Used by:

Batch extraction via ComputeAndProcessKaldiPitch; MFA-style feature pipelines that append pitch to MFCC (paste-feats).

MatrixF knf::ComputeAndProcessKaldiPitch(const PitchExtractionOptions &pitch_opts, const ProcessPitchOptions &process_opts, const float *wave, int32_t n)

Batch pitch extraction (kaldi's ComputeAndProcessKaldiPitch).

Combines the raw pitch extraction and the post-processing in one call; the output equals what kaldi's compute-and-process-kaldi-pitch-feats produces for the same input and options. It is sensitive to the variables in pitch_opts that relate to online processing, i.e. max_frames_latency, frames_per_chunk, simulate_first_pass_online, recompute_frame.

Parameters:

  • pitch_opts -- [in] Raw pitch extraction options.

  • process_opts -- [in] Post-processing options.

  • wave -- [in] Pointer to a 1-D array of n waveform samples (as returned by a WAV reader; kaldi semantics, i.e. raw int16 magnitudes, not divided by 32768).

  • n -- [in] Number of samples in wave.

Returns:

Feature matrix of shape (num_frames, process_opts.Dim()).
